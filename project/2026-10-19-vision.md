# Cappy — vision

*2026-10-19 · Ben Syverson & Claude · status: agreed direction*

**Cappy is SleepyHollow for native Mac apps.** It looks at a running app's real window and tells an agent what a person would see and hear: the composited pixels, the accessibility tree, and the controls' states. It can also press, type and pick through that same accessibility layer. It is a spiritual sibling of `sleepy`, down to the repo layout and the verbs: an agent that knows one should be able to use the other without re-reading the help.

## Why

Penumbra (the first user) verifies its UI with `scripts/probe`, which plays a script inside the app and captures views in-process with `cacheDisplay`. On 2026-10-19 that capture misled a whole design review (Penumbra `project/2026-10-19-inspector-layout.md`, leaf knVkPr):

- Checkboxes and pop-up bezels were missing.
- Secondary label colors on the panel's material came out black, and a drag handle came out white on white.
- A "+" button that the real app hid was drawn as if it were visible.

All of these happen at the layer and window-server level, where an in-process `draw(_:)` path cannot see. Only the composited window shows the truth.

Penumbra's gotchas name two more gaps that only an outside process can close:

- **SwiftUI builds its accessibility tree only while an assistive app is connected.** Unit tests see an empty tree, so VoiceOver labels are tested as strings, never as the tree a user hears.
- **Synthetic clicks never reach SwiftUI controls,** even inside their own app. So header clicks, buttons and menus are hand checks.

An external process that holds the Accessibility permission is an assistive app, and its accessibility actions (`AXPress`, setting `AXValue`) work through a different path than event injection.

## Philosophy

SleepyHollow's six rules hold here unchanged (see `../sleepyhollow/project/2026-08-20-vision.md`):

- stdout is the API.
- Exit codes are a contract: 0 success, 1 a clean negative, 2 usage, 3 timeout, 4 target not found (sleepy: load failure), 5 environment (here, a missing permission).
- The bare command is a primer, and `<verb> --help` teaches the verb.
- Everything terminates.
- Never a plausible wrong answer: a capture that could not see something says so rather than drawing a guess.

## Targets: the one place it differs from sleepy

sleepy's verbs take `<url>` (ephemeral) or `--session <name>` (live). Cappy's are the same shape:

- `<app>`: a running app by bundle ID, name or `pid:<n>`. It narrows with `--window <title|index|id>` and defaults to the frontmost window of that app.
- `--session <name>`: an app Cappy launched with `cappy open` and tracks by name (path, arguments, environment), so a test can launch a build, act, capture and `close` it.

## Verbs, mapped to sleepy

| sleepy | cappy | What it does here |
|---|---|---|
| `load` | `load` | Is the target there? Report the app, pid, its windows (title, frame, key/main, on-screen), whether it's active, and its appearance (light/dark). |
| `shot` | `shot` | The composited window from ScreenCaptureKit: the whole window, one element (`--element <ax query>`), or a rect. Works while the window is behind others, and never raises it. `--scale`, `--out`. |
| `ax` | `ax` | The accessibility tree in sleepy's outline format, one node per line (`checkbox "Visible" (checked)`, `button "Add Stroke"`, `heading "Position" (expanded)`), or `--format json` with frames. `--budget`, `--depth`. |
| `query` | `query` | Match elements by role, name, value or identifier, and report each one's frame, enabled, focused, hidden and on-screen state, and its actions. |
| `find` | `find` | Find text anywhere in the tree (titles, values, labels). Exit 0 if found, 1 if not. |
| `contrast` | `contrast` | For each text element, sample the real pixels under its frame from a `shot` and check WCAG contrast against its background. Exit 1 on any failure. This would have caught the white handle. |
| `overflow` | `clip` | Elements whose frames fall outside their window or their container. Exit 1 if any do. |
| `click` | `press` | Perform `AXPress` (or a named action, `--action AXShowMenu`) on a queried element. With `--point x,y`, post a real event at a window point instead. |
| `fill` | `fill` | Set a field's value (`AXValue`) and confirm it, or `--type` it as keystrokes. |
| `submit` | `pick` | Choose an item from a pop-up or menu by title. |
| `open`, `close`, `sessions` | `open`, `close`, `sessions` | Launch an app under a name and quit it; list and reap them. |
| `console` | `log` | The unified log for the target's process over a window of time (`--since`, `--predicate`). |
| `recipes`, `doctor` | `recipes`, `doctor` | Goal-to-verb routing; and diagnose the environment: permissions granted (Screen Recording, Accessibility), helper signature, macOS version. |

sleepy's `dom`, `style`, `pdf`, `archive`, `wire`, `eval`, `jars` and `cookies` have no native counterpart and stay out.

## Repo layout, mirrored

- **`Cappy`**: the library, with `Core` (exit status, errors), `Host` (finding apps and windows, permissions), `Operations` (one per verb), `Output` (outline and JSON writers shared in shape with sleepy) and `Session`.
- **`CappyCLIKit`**: the ArgumentParser options shared across verbs.
- **`cappy`**: the thin executable.
- **`TestSupport`** and **`CappyTests`**: a small fixture app (AppKit and SwiftUI windows with known controls) that the tests launch and inspect.
- **Repo files:**
  - `project/`: vision, plans, gotchas, backlog, background and recipes.
  - `scripts/`.
  - `AGENTS.md`, generated by `agents` with the same modules as sleepy (`.agents.yaml`).
  - `README.md`, written in sleepy's voice.
  - Install with `swift package experimental-install --product cappy`.

## Rulings (Ben, 2026-10-19)

All four recommendations were accepted ("Yes, that all sounds good"):

1. **Permissions live in a small signed helper app** (LSUIElement), not the terminal. The `cappy` CLI asks it over XPC, the way sleepy's `open` drives a helper process. The grants stay scoped to Cappy and survive rebuilds as long as the signing identity is stable. Granting them to the terminal or to Claude Code was the alternative, but every command run there would then hold them.
2. **Penumbra's probe gains a step that runs a `cappy` command** against the probe's own app and saves its output beside the capture, so one script reports both.
3. **The first cut is `load`, `shot`, `ax`, `query`, `find`, `press` and `doctor`** (plus `recipes` and the bare primer, which every sleepy-shaped tool has). That covers the 2026-10-19 capture failures and Penumbra knVkPr's hand checks. `contrast`, `fill`, `pick`, `clip`, sessions and `log` come next.
4. **MIT, with an embeddable library,** like sleepy.
